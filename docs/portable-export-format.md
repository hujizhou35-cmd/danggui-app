# 当归可读导出格式

当归的“可读导出”是一个本地生成的 ZIP 文件，用于长期阅读、手工归档和向其他工具迁移。它不是数据库恢复包；需要完整还原应使用 `.dgbak` 备份。

## 包内容

每个导出包仅包含下列文件：

- `manifest.json`：格式版本、App 标识与版本、数据库 schema 版本、UTC 创建时间、数据集 ID、导出范围、记录数、文件长度与 SHA-256。
- `data.json`：可机读数据，保留实体、文档块和出处字段。
- `markdown/tasks.md`：事项、计划、日期、提醒与正文。
- `markdown/past.md`：当前“过往”正文以及原始来源事件账本。
- `markdown/notes.md`：笔记和正文。
- `markdown/folders.md`：笔记文件夹。

JSON 对象的键和各类记录都使用稳定顺序。所有文本统一使用 UTF-8。

## 导出范围

`scope.kind` 当前支持：

- `full`：全部事项、过往、笔记和文件夹，包括未永久清理的软删除记录。
- `pastAll`：仅导出当前完整“过往”自由文档与全部原始来源元数据，事项、笔记和文件夹为空。
- `pastDateRange`：按 `completion_local_date` 闭区间筛选原始过往事件。
- `pastSelection`：仅保留用户主动选中的自由文本。JSON 和 Markdown 都明确标记这是用户选文，并且不附会任何来源事件、原始部件或锚点关系。
- `noteIds`：按明确笔记 ID 集合导出。不存在的 ID 不会生成伪记录。
- `noteFolder`：按文件夹 ID 导出其中笔记；空文件夹仍会保留文件夹元数据。

## “过往”的真实性规则

“过往”是可自由编辑的长文档。用户可以拆分、合并、改写或删除由事项生成的文档块，因此不能在之后精确断言某段当前正文仍属于某一日。

因此，日期范围导出遵守以下约定：

1. `past.events` 仅包含范围内的来源事件，并原样保留 `source_snapshot_json`、`source_sha256`、原始部件和锚点状态。
2. `past.currentDocument` 总是包含当前完整正文，不冒充“已按日期裁剪”。
3. `selectionPolicy` 与 Markdown 顶部会明确说明这一点。

这一规则使导出同时保留“用户现在看到的文本”与“当时真正写入的来源快照”，而不会伪造两者之间的对应关系。

## 完整性与安全边界

- `manifest.json.files` 记录每个负载文件的字节数与 SHA-256，`contentSha256` 再对文件哈希集合做总结哈希。
- 导出完成前会重新解包并校验所有长度与哈希，通过后才将 `.partial` 文件原子重命名为 `.zip`。
- 校验器拒绝重复路径、绝对路径、路径穿越、符号链接、未知文件和超限大小。
- 生成服务只在操作系统临时目录下写入，不包含任何网络上传逻辑。

注意：ZIP 本身未加密，因为其定位是“可读导出”。如需加密保管，请使用当归的加密 `.dgbak` 备份。
